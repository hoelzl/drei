# Drei

**Drei Resembles Emacs Intentionally.** Drei is an Emacs-like terminal editor built as a demanding example of agent-first software development and as a real-world test subject for [TermVerify](https://github.com/hoelzl/termverify).

Drei follows Eine ("Eine Is Not Emacs") and Zwei ("Zwei Was Eine Initially"), editors associated with the Lisp Machine tradition. The goal is not to clone all of GNU Emacs. It is to build a coherent, extensible editor whose semantics and terminal behavior agents can develop and verify autonomously.

## Status

Eighteen merged vertical slices. Two arcs have shipped and been joined: the **editor** (slices 1–7 and 12 — text, kill ring, mark/region, undo, the minibuffer and find-file, multiple buffers and windows) and the **ACP client** (slices 8–11 and 13 — the subprocess port, the NDJSON framing codec, the session state machine, `session/update` translation, and the approval bridge). Slices 14–16 made the ACP arc reachable from the shipped executable — an agent buffer per session, an event-driven input stream with resize, and the pump that spawns the child and folds its answers into a displayed buffer — so `C-c a` starts a real turn in the real editor. Slices 17–18 fixed the exit keys: `C-g` is `keyboard-quit`, and `C-x C-c` offers to save before ending the run.

### Editor

Supported commands: insert printable text, `C-f`/`C-b` horizontal movement, `C-k` kill-line, `C-y` yank, `M-y` yank-pop, `C-@` set-mark, `C-w` kill-region (point↔mark as one ring entry, point at the kill start, forward/backward direction recorded), `M-w` copy-region-as-kill (ring push without deleting, never sets modified), `C-x C-x` exchange-point-and-mark, `C-/`/`C-x u`/`C-_` undo (session-side stack of inverse patches, capacity 100; one group per text-changing command; consecutive undos descend; any event-emitting non-undo command breaks the descent and a following undo redoes; a fresh edit truncates the redo tail — deviation from stock Emacs's redo reachability, registry; undo restores point and mark from the group and *derives* the modified flag by comparing the resulting text with the buffer's last-saved text, so undoing past a save reports modified; nothing-to-undo is a silent no-op that leaves the descent direction alone), `C-x C-f` find-file through the minibuffer (prompt on the echo row; printable input, `DEL` backspace, `RET` accept, `C-g` abort; an already-open file selects its buffer, a new file creates one — basename id, `<N>` suffix on collision; a missing file or missing directory yields an empty unmodified buffer, other read errors leave the buffer untouched with `OpenFailed`; abort closes the prompt without quitting and without touching the buffer or mark), `C-x C-s` save through an injected file port, `C-x b` switch-to-buffer (empty input selects the MRU other buffer), `C-x 2`/`C-x o`/`C-x 1` split/cycle/collapse stacked windows with per-window points (each pane renders its buffer with its own modeline; the echo row is shared), `C-c a` agent prompt (opens a text prompt whose accepted text becomes an ACP turn — see below), `C-g` keyboard-quit (deactivates the mark, echoes `Quit`, cancels a pending prefix, aborts a minibuffer prompt — and never exits), and `C-x C-c` exit, which offers to save first: each modified file-visiting buffer is offered `Save file <path>? (y or n) ` in creation order, and if anything is still modified when the offers are done — including a buffer with no file, which Drei cannot save at all — `Modified buffers exist; exit anyway? (y or n) ` must be answered before the run ends. At an offer `y` writes the file and moves on and `n` leaves it untouched; **at that last question `y` ends the run and the unsaved buffers are gone** — it is the confirmation, not another save — while `n` leaves the editor running with everything intact. `C-g` abandons the exit at any point and leaves already-saved buffers saved; every other key, `RET` and `DEL` included, is ignored so a reflex cannot answer a question about losing work. A save that fails names itself on the next prompt (`Modified buffers exist; exit anyway? (y or n) [/tmp/notes.txt: permission-denied]`) rather than letting a failed write read as a successful one; the note trails the question because the echo row is clipped rather than wrapped, and the question is the half that must survive a narrow frame. Emacs's `SPC`/`DEL`/`!`/`.`/`q`/`C-r` answers and its `yes`-typing final confirmation are deliberate deviations (registry). Arrow, function, and other escape-sequence keys are assembled into one symbolic key (`<up>`, `<csi:…>`, `<ss3:…>`, `<ext:…>`) and left deliberately unbound — they do nothing rather than typing their bytes into the buffer; assembly is a pure function of the character stream, with no `escape-time` clock. Line endings are detected per buffer on visit: a uniformly-CRLF file is held LF-separated and written back as CRLF, anything else (LF, mixed, lone CR) round-trips verbatim, and a buffer with no file text to imitate writes LF on every platform. The mark lives on the frozen `BufferValue` and follows Emacs marker adjustment on every edit (insert before shifts, insert AT stays before, delete shifts/clamps — parity-pinned); region kills get their own `RegionKilled` event so mark state stays derivable from the transcript. Undo history, yank state, and the kill-chain flag live in a per-buffer record (undoing an interleaved history replays exactly that buffer's edits — property-pinned); the session-owned kill ring (capacity 60) appends consecutive kill-lines, opens a fresh entry for region kills, and rotates a cursor for yank-pop; undo does not touch it. While the minibuffer is open only its four commands act (everything else is a silent no-op, incl. nested `C-x C-f` — no recursive minibuffer); the harness routes keys at a single site. `drei [FILE]` opens a file; the modeline shows the `**`/`--` modified indicator covering every text-changing event (`TextInserted`/`TextKilled`/`TextYanked`/`TextYankPopped`/`RegionKilled`) and undo/redo restoration. Immutable records cross the session boundary; `BufferObservation` exposes the mark and the minibuffer state and `SessionObservation` adds the whole-session read model (buffer names, one `WindowObservation` per pane, focused index); all filesystem access sits behind the `FilePort`. The shipped executable is proven by TermVerify ConPTY scenarios (save, kill/yank, yank-pop prefix, undo via `C-x u` with a live `\x1f`/`C-/` byte arm, find-file accept with live `\x0d` RET and `\x7f` DEL arms, find-file abort, window split/focus/collapse, and buffer switching); `M-y`/`M-w` assemble ESC+letter in the byte loop (ConPTY swallows bare ESC — termverify#169) and `C-@` is undeliverable on the Windows console (msvcrt treats NUL as an extended-key prefix — verified live, registry deviation), both proven in-process through the same `run_editor` loop. Pinned GNU Emacs differential scenarios guard parity for insertion, movement, save, non-append kill/yank, first yank-pop, forward/backward region kill, copy with clean modified flag, marker adjustment, single undo (text/point/modified), find-file semantics (existing/missing/missing-directory), MRU switch-to-buffer, find-file buffer reuse, and per-window points across focus round-trips. The append chain, pop cycle, mark-deactivation-on-edit, no-mark no-ops, yank-not-pushing-mark, mark-ring absence, undo grouping, redo truncation, descent gating, undo capacity, empty-input no-op accept, no recursive minibuffer, no minibuffer keymap, directory-path rejection, `<N>` numeric collision suffix vs uniquify, `C-x 2` too-small no-op, vertical-only window stacks, no kill-buffer, and minibuffer default naming are intentional deviations (registry). The slice-7 wholesale-replace/discard hazard is resolved (find-file now creates per-file buffers). Modes, kill-buffer, horizontal splits, and extensions remain deferred.

### Agent integration (ACP)

Press `C-c a`, type a prompt, press `RET`: Drei launches the configured agent, runs an ACP turn, and streams the answer into an `*agent*` buffer beside the one you were editing. Drei speaks the [Agent Client Protocol](https://agentclientprotocol.com) as the *client*, pinned to the official Python SDK 0.9.0 (the revision the `hermes acp` peer uses). Every module in `drei.acp` stays pure — none of them imports `subprocess` or `asyncio` or touches a pipe:

- **`ProcessPort`** (`src/drei/process.py`) — the subprocess effect boundary for one-shot runs: blocking run-to-completion, launch failures normalized to tokens, the captured run recorded as one immutable `DeliverProcessOutput` delivery.
- **`StreamingProcessPort`** (`src/drei/streaming.py`) — the second process port, for the long-lived child Drei holds a conversation with. Separate from `ProcessPort` rather than a widening of it, so the simple heavily-used port never grows lifecycle concerns. Bytes in, bytes out, no framing.
- **`drei.acp.codec` / `drei.acp.messages`** — NDJSON framing and the JSON-RPC 2.0 envelope model. A malformed line is a `ProtocolError`, and frames parsed before it are kept, not discarded.
- **`drei.acp.machine`** — the session lifecycle (`initialize` → `session/new` → `session/prompt` → `session/update`* → completion/cancel) as an immutable value folded over inbound messages, emitting outbound messages and typed `SessionEffect`s. Malformed and out-of-phase input yields a `ProtocolError` effect, never an exception.
- **`drei.acp.transcript`** — the pure fold from effects to rendered transcript text; agent text enters the editor only as a `Command` crossing the same dispatch boundary a keystroke crosses. Agent diffs are rendered into the transcript, never applied.
- **The approval bridge** — `session/request_permission` opens a *choice* minibuffer listing the agent's options; `y`/`s`/`a`/`n` pick a scope explicitly, `RET` grants only `allow_once` (the option order is agent-controlled, so accept must never grant a broader scope), abort answers `cancelled`. A session-scoped auto-approval cache keyed on tool identity **plus arguments** — never the per-call `toolCallId` — honours `allow_session`/`allow_always` without re-prompting, and resets on a new session. Anything malformed or ambiguous re-prompts the human.

- **The pump** (`src/drei/pump.py`) — the adapter that joins them. It owns the `AcpMachine` and the decoder (the editor session never holds either, so replay never has to reproduce protocol phase), spawns the child on the first `C-c a` and not before, drains every frame a read delivered and folds them into **one** delivery, writes the human's permission answer back on the wire, and terminates the child in `run_editor`'s `finally`. Agent bytes reach it as events on the same totally ordered input queue as keystrokes — with keys in a priority lane, so a paragraph of streamed text never delays a keypress. The child's stderr and any launch failure go to an `*agent-log*` buffer, as a normalized token rather than a traceback: `drei file.txt` on a machine with no agent installed is exactly the editor it was.

Configure the agent with `--agent-command`, repeated once per argument (default: `hermes acp`). The end-to-end evidence drives a fake 0.9.0 agent through the shipped executable over ConPTY.

**Not yet wired.** Turn cancellation: `AcpMachine.cancel()` and `AbortPendingPermissions` both exist and nothing triggers them. The blocker is gone — slice 17 made `C-g` `keyboard-quit` rather than the exit key, so it is free to mean "cancel the turn in flight" as [design 0005](docs/agent/design/0005-acp-pump.md) D5 wants. See `docs/technical-debt.md`.

## Setup

```bash
uv --no-config sync --all-groups --locked
uv --no-config run pytest --cov --cov-report=term-missing
uv --no-config run drei --version
```

Install both local hook stages once:

```bash
uv --no-config run pre-commit install --hook-type pre-commit --hook-type pre-push
```

See `CONTRIBUTING.md`, `AGENTS.md`, and `docs/knowledge/index.md` before changing behavior.

## Direction

Drei will expose deterministic command execution and immutable semantic evidence through an in-process harness and a terminal frontend. Stable runtime-owned identity shells will own immutable or controlled-private domain values behind a serialized, atomic command boundary; whole-model immutability is not required. Tests progress from unit/property contracts to replayable scenarios and TermVerify-driven end-to-end evidence. GNU Emacs differential tests are selective and explicit; intentional Drei behavior remains possible.
